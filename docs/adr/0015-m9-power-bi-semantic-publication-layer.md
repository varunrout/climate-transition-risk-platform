# ADR 0015: M9 Power BI Semantic Publication Layer

## Status

Accepted for code/data layer. Power BI Desktop visual assembly remains pending
because Power BI Desktop is not available in the current execution environment.

## Context

M9 turns the analytical platform into a decision-facing Power BI product. The
dashboard must consume existing silver/gold outputs rather than recomputing
risk methodology, scenario generation, backtesting, or structural-break logic in
DAX.

The active production score is `v2_energy`. The v1 score remains available for
comparison. The production scenario method remains `empirical_bootstrap_v1`.
M7 structural-break outputs remain diagnostic only and must not select the
production forecast or enter `risk_score_v2_energy`.

## Decision

Create a deterministic BI publication layer under `gold/bi/`:

- `country_overview.parquet`
- `country_timeseries.parquet`
- `risk_components.parquet`
- `scenario_quantiles.parquet`
- `backtest_metrics.parquet`
- `energy_indicators.parquet`
- `regime_diagnostics.parquet`
- `run_metadata.parquet`

The publication layer is generated by:

```text
climate-risk build-bi --scenario-target-year 2030
```

The BI layer is downstream and separately recoverable. It does not update
`latest_successful_run.json`, does not enter the fail-closed production publish
barrier, and does not change Azure infrastructure. This avoids corrupting the
core production score publication if a reporting-only reshape fails.

## Refresh Strategy

Power BI should consume local exported tables for portfolio/demo work or ADLS
Gen2 `gold/bi/` tables with Entra authentication for cloud refresh. The refresh
cadence should follow the existing weekly production pipeline cadence. The
report must show the latest successful run, score version, Git SHA, image
digest when available, config hash, and source snapshot IDs.

No new Azure services are required.

## Consequences

- Python remains the source of truth for scoring, backtesting, scenarios, and
  regime diagnostics.
- DAX should stay thin and semantic.
- Risk score and data confidence remain separate fields.
- Structural-break diagnostics are labelled as diagnostic-only.
- PBIX/manual Desktop assembly can proceed from a stable semantic contract.
