# Power BI Refresh and Authentication

## Recommended Paths

### Portfolio / Demo Mode

Use local `gold/bi/*.parquet` exports generated by:

```powershell
poetry run climate-risk --no-json-logs build-bi --scenario-target-year 2030
```

Power BI Desktop can import the files from:

```text
data/lake/gold/bi/
```

The native project (`powerbi/ClimateTransitionRisk.pbip`) reads this path
through a single Power Query text parameter, `GoldBiFolderPath`, referenced
by every table's `Parquet.Document(File.Contents(...))` partition, rather
than a literal path hardcoded per table -- update that one parameter
(Transform data > Manage Parameters) to point at your local repo checkout's
`data/lake/gold/bi/` folder.

This requires no paid Power BI or Azure service.

### Cloud Refresh Mode

Use ADLS Gen2 `gold/bi/` with Entra authentication. The existing storage
account, managed identity model, and ADLS filesystems are sufficient. Do not
introduce SQL databases, Synapse, Fabric capacity, or Power BI Premium capacity
only to serve these BI tables.

## Refresh Cadence

The production Azure pipeline runs weekly. The report should show:

- latest successful run timestamp
- active score version
- latest model eligible year
- source snapshot IDs
- publish status

Do not imply real-time updates.

## Production Integration Status

The `build-bi` command is downstream and separately recoverable. It does not
change the fail-closed publication pointer. If BI publication is later added to
the Azure scheduled job, it should run after validated gold analytics and should
not corrupt core score artifacts if the BI reshape fails.

## Authentication Rules

Allowed:

- Entra user authentication for Desktop development
- existing managed identity for Azure runtime, if later enabled

Not allowed:

- storage account keys
- SAS tokens
- connection strings
- embedded credentials
